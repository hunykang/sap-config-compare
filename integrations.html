FI 외부 연계 설명

FI는 혼자 돌지 않습니다. 경비·인사·결재·세금계산서·신고 업무는 바깥 시스템에서 일어나고, 그 결과가 FI 전표로 들어옵니다. 여기에 더해 대량 전표를 만드는 분개엔진, 구매·주문·생산·물류·정산을 맡는 SCM 솔루션, 펌뱅킹·CMS, 내부회계관리, 관리회계 수익성분석도 같은 방식으로 연결했습니다. 이 페이지는 그 외부 시스템을 프로세스 지도의 해당 노드에 스며들게 연결한 설명입니다. 업체별 제품 소개가 아니라 기능과 FI 접점 위주로 정리했고, 구매관리 절에서는 비교 기준이 되는 유형으로 아리바와 유사한 형태를 언급했습니다.

지도에서 노드를 누르면 상세 패널의 외부 연계 행에도 같은 내용이 뜹니다.

1. e-Accounting — 경비정산 · 매입세금계산서

지도 연결 일반전표·경비 처리 · 송장 검증

하는 일

  • 직원이 경비를 신청하면 증빙(영수증·세금계산서)을 붙여 정산합니다. 법인카드 사용분도 여기서 모입니다.
  • 거래처가 보내온 매입세금계산서를 수취해 송장 검증과 매핑합니다. 금액·세액·공급자 정보가 맞아야 반제가 됩니다.

FI 접점

경비 신청·승인 → 비용 / AP (일반전표·경비 처리) · 법인카드 정산
매입세금계산서 수취 → AP / GR-IR · 비용 / AP (송장 검증) · 역발행세금계산서는 매입자 쪽에서 발행해 관리

주의점

  • 증빙 없는 경비는 전표가 되어도 나중에 세무에서 틀어집니다. 증빙 보관과 전표는 한 세트로 관리합니다.
  • 매입세금계산서의 세액이 틀리면 부가세 신고까지 틀어지니, 수취 단계에서 매핑 검증이 중요합니다.

2. e-HR — 조직정보 · 급여정보 · 복리후생

지도 연결 조직·기준정보 · 인건비·퇴직급여

하는 일

  • 조직·인사 정보를 관리합니다. 직원의 코스트센터(부서)가 여기서 정해집니다.
  • 매월 급여를 계산하고, 4대보험 같은 복리후생비와 퇴직급여를 산정합니다.

FI 접점

e-HR 월별 인건비 계산 → 전표 작성 → 회계팀 전송 → 급여 / 상여 · 미지급 인건비, 예수금 - 원천세, 복리후생비 - 4대보험 / 미지급비용일반
퇴직급여: 연초에 받은 계리액의 매월말 1/12씩 → 퇴직급여 / 퇴직급여충당금 (코스트센터 구분을 명확히)

주의점

  • 직원의 코스트센터를 e-HR과 SAP에서 항상 동일하게 정비해야 합니다. 여기가 어긋나면 부서별 비용이 전부 틀어집니다.
  • 인건비 전표는 회계팀이 내역을 확인하고 승인한 뒤에 전기합니다.

3. 전자결재 — 내부통제 기안 · 전자증빙 보관

지도 연결 전표 승인 · 일반전표·경비 처리

하는 일

  • 지출·계약·전표 관련 기안을 전자결재로 올리고 승인받습니다. 내부통제의 흔적이 기안-승인 이력으로 남습니다.
  • 승인된 내역에 딸린 증빙을 전자 형태로 보관합니다. 종이 증빙을 찾는 일이 사라집니다.

FI 접점

기안 → 승인 → 임시전표 전기 (전표 승인 노드) · 증빙은 전표와 함께 보관되어 나중에 조회 가능

주의점

  • 승인 전에 장부에 잡히면 안 됩니다. 임시전표 상태와 전기 상태를 구분하는 것이 통제의 핵심입니다.
  • 증빙이 없는 승인은 나중에 감사에서 지적됩니다. 기안-증빙-전표 세 가지가 한 건으로 묶여야 합니다.

4. 전자세금계산서발행 — 매출 · 영세율 · 계산서 · 역발행

지도 연결 대금청구·세금계산서 · 송장 검증

하는 일

  • 매출이 확정되면 매출세금계산서를 발행합니다. 수출처럼 영세율이 적용되는 거래는 영세율세금계산서로 나갑니다.
  • 면세 거래에는 세금계산서가 아니라 계산서를 발행합니다.
  • 역발행세금계산서는 매입자 쪽에서 발행하는 형태로, 송장 검증 쪽에서 관리합니다.

FI 접점

대금청구 → 매출채권 / 매출 · 부가세 (매출세금계산서·영세율·계산서 발행)
역발행 수취 → AP / GR-IR (송장 검증)

주의점

  • 영세율과 면세(계산서)는 세법상 성격이 다릅니다. 세금계산서로 잘못 나가면 신고가 틀어집니다.
  • 발행분과 수취분은 각각 매출·매입 합계표로 모여 부가세 신고의 재료가 됩니다.

5. 부가세 및 원천세 신고

지도 연결 재무제표·세무신고

하는 일 — 월별 / 분기 주기로 합계표를 확인하고 전자 신고 파일을 만듭니다

  • 세금계산서 합계표: 세금계산서에 대한 부가세를 확인합니다.
  • 계산서 합계표: 계산서에 대한 부가세를 확인합니다.
  • 신용카드 수취명세서: 신용카드 사용분(매입·매출)의 부가세를 확인합니다.
  • 수출입 명세서: 영세율 내역을 확인합니다.
  • 부동산 임대공급 관련 신고: 간주임대료를 포함해 임대공급 내역을 정리합니다.
  • 공통매입세액 안분: 과세사업과 면세사업을 함께 영위하는 겸영사업자가, 공통으로 사용한 재화·용역의 매입세액을 과세 부분과 면세 부분으로 나눕니다. 근거는 부가가치세법 시행령 제61조 제1항이며, 예정신고 때 나눈 금액은 확정신고 때 정산합니다.
  • 원천세: 급여·사업소득 등에서 떼는 세금을 신고합니다. 급여 전표의 예수금-원천세와 연결됩니다.

FI 접점

합계표 확인 (월별/분기) → 전자 신고 파일 생성 → 홈텍스 신고
공통매입세액 안분 → 불공제 매입세액 확정 → 확정신고 시 정산

주의점

  • 합계표가 틀리면 신고가 틀립니다. 신고 전에 세금계산서·계산서·신용카드 세 가지 합계표를 각각 확인하는 것이 순서입니다.
  • 공통매입세액 안분은 사업장별로 계산한 뒤 합산해 신고하는 구조라, 사업장이 여럿이면 안분 기준을 먼저 통일해야 합니다.

6. 펌뱅킹·CMS — 입출금 · 집금 · 가상계좌 · 전자어음 · B2B · 환율

은행과 자금을 연결하는 펌뱅킹·CMS의 세부 기능은 입출금, 집금, 가상계좌, 전자어음, B2B, 환율입니다. 참고로 이 기능들을 따로 도입하지 않고, 펌뱅킹 솔루션 하나로 전부 서비스하는 형태도 있습니다. 은행·규모에 따라 통합형으로 가기도 하고, 필요한 것만 골라 붙이기도 합니다.

6-1. 펌뱅킹·CMS — 입출금 자동 대사 · 지급 파일 전송

지도 연결 지급 · 입금·반제 · 자금계획·유동성

하는 일

  • 은행과 ERP를 전용선·인터넷으로 연결합니다. 은행 입출금 내역을 자동으로 가져오고, ERP에서 만든 지급 파일을 은행에 전송합니다. 은행 사이트에 일일이 들어가 확인하던 일을 없애는 것이 목적입니다.
  • 집금 — 여러 은행·계좌에 흩어진 자금을 대표 계좌로 모으는 기능입니다. 계좌별 잔액을 일일이 옮기지 않고 정해진 규칙으로 자동 이체합니다.
  • 펌뱅킹 솔루션 중에는 입출금, 집금, 가상계좌, 전자어음, B2B, 환율까지 이 절의 세부 기능을 하나로 서비스하는 형태도 있습니다. 따로따로 붙이는 것이 아니라 은행 채널 하나로 묶어서 쓰는 방식입니다.

FI 접점

은행 입출금 내역 자동 수신 → 입금 자동 대사·반제 (입금·반제) · 지급 파일 전송 → AP / 보통예금 (지급) · 은행 잔액 실시간 조회 → 자금계획·유동성

주의점

  • 은행 코드·계좌 매핑이 틀리면 대사가 전부 틀어집니다. 계좌를 새로 만들면 매핑부터 확인합니다.
  • 대사 실패분(금액·거래처가 안 맞는 입금)은 따로 모아 처리해야 합니다. 실패분을 방치하면 미반제 채권이 쌓입니다.
  • 지급 파일 전송은 결재·권한과 묶어야 합니다. 파일이 나가면 되돌리기 어렵습니다.

6-2. 가상계좌 — 거래처별 · 주문별 입금 식별

지도 연결 입금·반제

하는 일

  • 거래처별·주문별로 가상계좌를 발급합니다. 입금되면 어느 거래처·어느 주문의 입금인지 자동으로 식별해 반제합니다. 입금자명을 일일이 대조하던 일을 없앱니다.

FI 접점

가상계좌 발급 → 입금 → 자동 식별 → 보통예금 / 매출채권 (입금·반제)

주의점

  • 가상계좌 채번 규칙(거래처별·주문별)을 먼저 정해야 합니다. 규칙이 섞이면 식별이 꼬입니다.
  • 미식별 입금(계좌는 맞는데 주문이 안 맞는 경우)은 따로 모아 처리합니다. 계좌 해지 시점도 관리해야 합니다.

6-3. 전자어음 — 발행 · 배서 · 할인 · 결제

지도 연결 어음·입출금 관리

하는 일

  • 종이 어음 대신 전자어음을 씁니다. 발행·배서(양도)·할인·결제를 전자어음 시스템에서 관리하고, 만기·부도 여부까지 추적합니다.

FI 접점

전자어음 발행 → 받을어음 / 매출채권 · 배서·할인 → 어음 양도·할인 전표 · 만기 결제 → 보통예금 / 받을어음 · 부도 → 채권 전환·부도어음 처리 (어음·입출금 관리)

주의점

  • 만기 관리가 핵심입니다. 만기가 지난 어음이 방치되면 입금 계획이 틀어집니다.
  • 부도어음은 자동으로 채권으로 전환되는 것이 아니라, 부도 사유와 회수 가능성을 확인한 뒤에 처리해야 합니다.

6-4. B2B 전자결제 — 기업 간 외상매출채권 결제

지도 연결 입금·반제

하는 일

  • 기업 간 거래 대금을 은행을 통해 전자적으로 결제합니다. 판매기업의 외상매출채권을 기반으로 구매기업이 결제하고, 은행이 중계합니다.

FI 접점

매출채권 → B2B 결제 → 보통예금 / 매출채권 (입금·반제)

주의점

  • 결제 조건·수수료 부담 주체를 계약에서 먼저 정해야 합니다. 수수료를 누가 내는지로 입금액이 달라집니다.
  • 만기·할인 조건이 어음과 비슷하니, 만기 관리와 할인 전표 처리를 어음과 같은 기준으로 관리합니다.

6-5. 환율 자동 수신 — 고시환율 마스터 자동 업데이트

지도 연결 월결산

하는 일

  • 매일 고시환율을 자동으로 받아 환율 마스터를 업데이트합니다. 외화 거래·외화 채권·채무 평가의 기준이 되는 환율을 손으로 입력하지 않게 합니다.

FI 접점

고시환율 자동 수신 → 환율 마스터 업데이트 → 외화평가 (월결산) · 외화 채권·채무 평가 차이 전표

주의점

  • 환율 출처와 적용 시점(일별·월말)을 먼저 정해야 합니다. 출처가 바뀌면 평가 차이가 달라집니다.
  • 수신 실패일에 손으로 입력하면 나중에 대사가 안 맞습니다. 실패분은 재수신하는 것이 순서입니다.

7. 연결회계 솔루션

지도 연결 연결회계

하는 일

  • 각 자회사·사업장의 결산 데이터를 모아 연결 대상을 확정합니다.
  • 그룹 내부거래(내부 매출·매입, 내부 채권·채무)를 상계하고, 지분·투자 관련 연결 조정을 처리합니다.
  • 상계·조정 결과를 모아 연결재무제표를 작성합니다.

FI 접점

자회사 결산 데이터 수집 → 내부거래 상계 전표 (연결회계 노드) · 본지사 정리 → 연결재무제표 보고
상계가 안 맞으면 연결 단계에서 차이가 남으니, FI 내부거래 잔액이 먼저 맞아야 합니다.

주의점

  • 내부거래 상계는 양쪽 장부가 같은 금액·같은 기간이어야 성립합니다. 한쪽만 잡힌 내부거래가 연결에서 가장 많이 걸립니다.
  • 자회사마다 결산 일정·통화가 다르면 연결 일정이 늦어지니, 연결 일정과 환산 기준을 먼저 통일해야 합니다.
  • 연결 조정은 개별 회사 장부를 고치는 것이 아니라 연결 장부에서만 처리하는 것이 원칙입니다.

8. 분개엔진 솔루션 — 대량 거래데이터 자동 분개

지도 연결 일반전표·경비 처리 · 월결산

하는 일

  • 카드·보험·은행·통신처럼 거래가 대량으로 쏟아지는 곳에서, 거래데이터를 미리 정해둔 규칙(매핑 테이블)대로 전표로 바꿔 FI로 넘깁니다. 사람이 한 건씩 치는 전표가 아니라 하루 수만~수백만 건을 일괄 생성·검증·전기합니다.
  • 전표 패턴은 정형화되어 있지만 거래량은 많은 곳에서 씁니다. 금융회사가 대표적입니다.

FI 접점

거래데이터 수집 → 규칙 매핑 → 비용 / 수익 · 미수금 / 미지급금 전표 일괄 생성 (일반전표·경비 처리)
결산 시 → 조정분개 일괄 생성 (월결산) · 실패분은 오류 전표로 분리해 재처리

주의점

  • 매핑 규칙이 틀리면 틀린 전표가 대량으로 찍힙니다. 규칙 변경 시 소규모 시범 전기와 대사(원장 잔액·거래 합계 대조)가 필수입니다.
  • 실패분 재처리 프로세스(보류·재전송·수기 개입 기준)를 먼저 정해야 합니다. 실패분을 방치하면 월말에 한꺼번에 터집니다.

9. SCM 솔루션 연계 — 물류 · 구매 · 생산 · 주문 · 정산

SCM은 공급망 전체를 말합니다. FI와 만나는 지점만 다섯 갈래로 나눠 정리했습니다.

9-1. WMS·물류관리 — 입고 · 이동 · 출고 · 실사 · 배송추적

지도 연결 입고 · 재고 이동 · 재고실사 · 출고 · 이커머스 주문·정산

하는 일

  • 창고 안에서 일어나는 모든 움직임을 기록합니다. 입고·검수·적치, 창고 간 이동, 피킹·포장·출고, 반품, 재고실사까지, 실물의 위치와 수량을 바코드·스캔으로 남깁니다.
  • 로지스와 유사한 물류관리 솔루션은 WMS의 창고 실행과 배송 단계를 연결합니다. 출고된 화물이 어디까지 갔는지 실시간으로 추적하고, 배송완료 정보(도착 증빙 포함)를 다시 시스템으로 돌려보냅니다. 창고 안(WMS)과 창고 밖 배송이 한 흐름으로 이어지는 구조입니다.

FI 접점

입고 → 재고 / GR-IR · 창고 간 이동 → 재고 이동 기록(평가액 변동 없음이 원칙) · 출고 → 매출원가 / 재고 · 실사 차이 → 재고실사 과부족 전표
출고 후 → 배송추적 → 배송완료 확인 → 매출 인식(배송완료 시점) · 운송비 정산 (이커머스 주문·정산 노드와 연결)

주의점

  • 실물 이동과 전표 이동의 시점 차이(선입고·후전표)가 월말 재고 차이로 남습니다. 스캔 누락이 곧 재고 차이이니, 실사 전에 이동 기록부터 맞추는 것이 순서입니다.
  • 배송완료 확인 시점과 매출 인식 시점을 일치시켜야 합니다. 배송 중인데 매출이 먼저 잡히거나, 도착했는데 입금이 안 잡히면 이커머스 정산과 어긋납니다. 운송비 정산도 운송사 청구와 FI 지급을 대조해야 합니다.

9-2. 구매관리 솔루션 — 아리바와 유사한 소싱 · 계약 · 카탈로그 구매

지도 연결 구매요청·발주 · 송장 검증

하는 일

  • 공급업체를 등록·평가하고, 견적·입찰(소싱)로 단가를 정하고, 계약을 맺고, 단가를 카탈로그에 올려 현업이 골라 사게 합니다. 아리바와 유사한 형태의 구매관리 솔루션이 맡는 범위입니다.
  • 현업은 카탈로그에서 골라 구매요청을 올리고, 승인 흐름을 거쳐 발주가 나갑니다. 소모성 자재·수리용품 같은 간접자재(MRO) 구매도 이 흐름 안에 들어갑니다. MRO는 솔루션 이름이 아니라, 구매 대상의 한 예시입니다.

FI 접점

구매요청·발주 → 입고 → 송장 검증 → AP / GR-IR (매입채무) → 지급
계약·입고·송장 3-way 매칭이 핵심입니다. 계약단가·입고수량·송장금액이 맞아야 반제가 됩니다. 카탈로그 단가가 기준이라, 단가 변경은 계약·카탈로그에서 먼저 일어나야 합니다.

주의점

  • 계약단가와 송장단가가 어긋나면 3-way 매칭에서 걸립니다. 단가 변경·계약 변경 이력을 먼저 확인하는 것이 순서입니다.
  • 카탈로그에 없는 품목을 부서마다 제각각 사면 단가가 샙니다. 카탈로그 외 구매는 예외 승인으로 관리합니다.
  • 간접자재는 입고 즉시 비용으로 갈지 재고로 둘지 기준을, 계약·품목 기준과 함께 정해야 합니다. 자산성이 있는 공구와 소모품(비용) 구분도 마찬가지입니다.

9-3. MES 생산관리 — 실시간 생산실적

지도 연결 생산입고·재고평가 · 제조원가결산

하는 일

  • ERP의 생산계획과 현장 설비 사이에서, 작업지시를 내리고 실적(투입·산출·불량·작업시간)을 실시간으로 모읍니다. 계획이 아니라 현장에서 실제로 일어난 일을 기록하는 시스템입니다.

FI 접점

작업지시 → 생산실적 수집 → 생산입고 → 재고 / 생산원가 · 실제 투입·수율 집계 → 제조원가결산(표준/실제 차이) → 자재원장 결산

주의점

  • 실적이 늦게·틀리게 들어오면 원가와 재고가 함께 틀어집니다. 실적 확정 시점(당일 마감)과 결산 일정을 맞추고, 불량·재작업 실적 누락을 점검해야 합니다.

9-4. OMS 주문관리 — 전 채널 주문 · 재고 할당

지도 연결 판매오더 · 이커머스 주문·정산 · 출고

하는 일

  • 자사몰·마켓플레이스·오프라인 등 여러 채널의 주문을 한곳에 모아, 재고를 할당하고 출고할 창고·지점을 정하고, 배송·반품까지 주문 생애주기를 관리합니다.

FI 접점

주문 수집·재고 할당 → 출고 → 매출원가 / 재고 → 청구 → 매출채권 / 매출 → 수금·반품
주문취소·부분배송·반품이 생기면 매출 취소 전표와 재고 복귀를 같은 건으로 묶어야 합니다.

주의점

  • 채널별 주문번호·취소·부분배송이 FI 전표와 1:1로 안 맞으면 반제가 꼬입니다. 주문-출고-청구-반품의 건별 연결고리가 핵심입니다.

9-5. 이커머스 정산관리 — 채널별 매출 · 수수료 · 반품

지도 연결 이커머스 주문·정산 · 카드수금 · 입금·반제

하는 일

  • PG·마켓플레이스·배달앱 등 채널별로 흩어진 매출·수수료·반품·환불 내역을 모아 정산합니다. 채널마다 정산 주기·보류금·수수료 차감 방식이 다릅니다.

FI 접점

카드승인 → 카드미수금 / 선수금 → 배송완료 → 선수금 / 매출 · 매출원가 / 재고 → PG·채널 정산 입금 → 보통예금 / 카드미수금 · 지급수수료 → 반품·환불 → 매출 취소 · 재고 복귀

주의점

  • 채널별 정산서와 FI 입금을 대조하는 대사가 필수입니다. 정산 주기가 어긋나면 미수금이 쌓인 것처럼 보입니다.
  • 쿠폰·포인트 부담 주체(몰 자체 부담인지 입점사 부담인지)에 따라 매출 차감 처리가 달라지니, 정산 전에 부담 기준을 정해야 합니다.

10. 리스회계 솔루션 — IFRS 16 · 사용권자산

지도 연결 자산 취득 · 감가상각

하는 일

  • 리스 계약을 등록하고, 리스 기간·리스료·할인율로 사용권자산과 리스부채를 계산합니다. 매월 리스료·이자·상각 스케줄을 만들고, 계약 변경(기간 변경·리스료 변경)이 생기면 재측정합니다.
  • SAP의 표준 부동산 관리 기능이 FI·관리회계·자산회계와 연결되는 방식이고, 계약이 많은 회사는 전문 리스회계 솔루션을 붙이기도 합니다. 두 경우 모두 IFRS 16(한국 K-IFRS 1116호) 기준을 따릅니다.
  • Public 스콥 아이템 — 임차: 1T6(임차 회계), 21P(임차 회계 - 그룹 원장 IFRS), 34N(임차 회계 - 그룹 원장 US GAAP). 임대: 21Q(임대 회계), 전대 2SB, 2SA(그룹 원장 IFRS), 34O(그룹 원장 US GAAP), 그룹내 전대 2O9, 서비스 계약 21R.

FI 접점

리스 개시 → 사용권자산 / 리스부채 (자산 취득)
매월 → 이자비용 / 리스부채 · 상각비 / 사용권자산 감가상각누계액 (감가상각) · 리스료 지급 → 리스부채 감소 (지급)
계약 변경·종료 → 재측정 전표
임대인 — 운용리스: 리스료 수익 인식 · 금융리스: 리스채권 / 금융수익 인식

주의점

  • 리스 기간 판단(연장·종료 선택권을 행사할지)이 사용권자산·리스부채 금액을 좌우합니다. 계산 전에 계약서를 먼저 검토하는 것이 순서입니다.
  • 할인율(증분차입이자율)이 바뀌거나 리스료가 바뀌면 재측정이 필요합니다. 스케줄을 손으로 고치면 안 되고, 변경 사유와 함께 재측정해야 합니다.
  • 단기(12개월 이하)·소액자산 리스는 예외 적용이 가능합니다. 예외를 쓸지 말지는 회사 기준으로 먼저 정해야 합니다.
  • 리스료 구성(고정리스료·변동리스료·잔존가치보증)을 구분해야 합니다. 변동분은 리스부채에 안 들어가는 경우도 있습니다.
  • 보증금 현재가치할인차금 — 2608년 현재 Public 임차 리스 스콥(1T6·21P·34N)에서는 지원되지 않아 별도 수기 처리가 필요합니다.

11. 내부회계관리 솔루션 — 권한 분리 · 승인 이력 · 통제 평가

지도 연결 전표 승인

하는 일

  • 내부회계관리제도 운영을 돕습니다. 통제 설계·평가·증빙·감사 추적을 한곳에서 관리하고, 전표 승인 권한 분리, 증빙 의무화, 통제 테스트, 미비점 조치까지 이어집니다.

FI 접점

전표 생성 → 승인(권한 분리) → 전기 → 승인 이력·증빙 보관 (전표 승인) · 통제 테스트 → 미비점 조치 → 외부감사 대응 자료

주의점

  • 기안자와 승인자가 같으면 통제가 아닙니다. 권한 분리(SoD)가 내부회계관리의 출발점입니다.
  • 증빙 없는 전표는 통제 테스트에서 바로 걸립니다. 증빙 첨부를 전표 전기 조건으로 묶는 것이 안전합니다.
  • 통제 테스트는 연말에 몰아서 하지 말고 주기적으로 돌려야 합니다. 미비점은 조치 기한과 함께 관리합니다.

12. 관리회계 수익성분석 솔루션 — QSA와 유사한 형태 · 고객/제품/채널별 수익성

지도 연결 관리손익

하는 일

  • 매출·매출원가·판관비를 고객·제품·채널·지역별로 배부·집계해 수익성을 분석합니다. 재무제표 손익을 관리회계 관점(관리손익)으로 재구성하고, 예산 대비 실적·추세를 봅니다.

FI 접점

FI 전표·원가 데이터 → 매출/매출원가 실적 집계 → 판관비·영업외손익 배부 → 수익성 분석·보고 (관리손익)

주의점

  • 배부 기준(매출액·인원·면적 등)이 결과를 좌우합니다. 기준은 분석 전에 합의해야 하고, 중간에 바꾸면 추세가 끊깁니다.
  • FI 결산이 끝나야 분석이 확정됩니다. 가결산으로 본 분석은 잠정치라고 표기해야 합니다.
  • 수익성 단위(고객·제품·채널) 마스터가 정비되어 있어야 합니다. 마스터가 섞이면 분석도 섞입니다.

13. 자산관리 솔루션 — 바코드·RFID 자산 실사

지도 연결 자산 실사

하는 일

  • 자산에 바코드·RFID 태그를 붙이고, PDA·리더기로 실사합니다. 자산대장(위치·부서·사용자)과 실사 결과를 대조해 미발견 자산·잉여 자산을 가려내고, 위치 이동 이력까지 남깁니다.

FI 접점

태그 부착·실사 → 자산대장 대조 → 실사 차이 → 자산 조정 전표(과부족 처리) (자산 실사) · 위치·부서 변경 → 자산 마스터 변경 · 폐기 대상 식별 → 자산 폐기 노드와 연결

주의점

  • 태그가 떨어지거나 훼손되면 실사에서 빠집니다. 실사 전에 태그 상태부터 점검해야 합니다.
  • 실사 전에 자산대장부터 정리해야 합니다. 폐기·매각했는데 대장에 남아 있으면 차이가 계속 납니다.
  • 실사 차이는 원인 확인이 먼저입니다. 분실인지 대장 오류인지에 따라 처리(조정 전표·대장 정정)가 달라집니다.
  • RFID는 금속 자산·액체 근처에서 인식률이 떨어질 수 있습니다. 자산 특성에 따라 바코드와 RFID를 섞어 쓰는 것이 현실적입니다.
