FI 외부 연계 설명

FI는 혼자 돌지 않습니다. 경비·인사·결재·세금계산서·신고 업무는 바깥 시스템에서 일어나고, 그 결과가 FI 전표로 들어옵니다. 이 페이지는 그 외부 시스템을 프로세스 지도의 해당 노드에 스며들게 연결한 설명입니다. 특정 업체나 제품 이름은 쓰지 않고, 기능과 FI 접점만 정리했습니다.

지도에서 노드를 누르면 상세 패널의 외부 연계 행에도 같은 내용이 뜹니다.

1. e-Accounting — 경비정산 · 매입세금계산서

지도 연결 일반전표·경비 처리 · 송장 검증

하는 일

  • 직원이 경비를 신청하면 증빙(영수증·세금계산서)을 붙여 정산합니다. 법인카드 사용분도 여기서 모입니다.
  • 거래처가 보내온 매입세금계산서를 수취해 송장 검증과 매핑합니다. 금액·세액·공급자 정보가 맞아야 반제가 됩니다.

FI 접점

경비 신청·승인 → 비용 / AP (일반전표·경비 처리) · 법인카드 정산
매입세금계산서 수취 → AP / GR-IR · 비용 / AP (송장 검증) · 역발행세금계산서는 매입자 쪽에서 발행해 관리

주의점

  • 증빙 없는 경비는 전표가 되어도 나중에 세무에서 틀어집니다. 증빙 보관과 전표는 한 세트로 관리합니다.
  • 매입세금계산서의 세액이 틀리면 부가세 신고까지 틀어지니, 수취 단계에서 매핑 검증이 중요합니다.

2. e-HR — 조직정보 · 급여정보 · 복리후생

지도 연결 조직·기준정보 · 인건비·퇴직급여

하는 일

  • 조직·인사 정보를 관리합니다. 직원의 코스트센터(부서)가 여기서 정해집니다.
  • 매월 급여를 계산하고, 4대보험 같은 복리후생비와 퇴직급여를 산정합니다.

FI 접점

e-HR 월별 인건비 계산 → 전표 작성 → 회계팀 전송 → 급여 / 상여 · 미지급 인건비, 예수금 - 원천세, 복리후생비 - 4대보험 / 미지급비용일반
퇴직급여: 연초에 받은 계리액의 매월말 1/12씩 → 퇴직급여 / 퇴직급여충당금 (코스트센터 구분을 명확히)

주의점

  • 직원의 코스트센터를 e-HR과 SAP에서 항상 동일하게 정비해야 합니다. 여기가 어긋나면 부서별 비용이 전부 틀어집니다.
  • 인건비 전표는 회계팀이 내역을 확인하고 승인한 뒤에 전기합니다.

3. 전자결재 — 내부통제 기안 · 전자증빙 보관

지도 연결 전표 승인 · 일반전표·경비 처리

하는 일

  • 지출·계약·전표 관련 기안을 전자결재로 올리고 승인받습니다. 내부통제의 흔적이 기안-승인 이력으로 남습니다.
  • 승인된 내역에 딸린 증빙을 전자 형태로 보관합니다. 종이 증빙을 찾는 일이 사라집니다.

FI 접점

기안 → 승인 → 임시전표 전기 (전표 승인 노드) · 증빙은 전표와 함께 보관되어 나중에 조회 가능

주의점

  • 승인 전에 장부에 잡히면 안 됩니다. 임시전표 상태와 전기 상태를 구분하는 것이 통제의 핵심입니다.
  • 증빙이 없는 승인은 나중에 감사에서 지적됩니다. 기안-증빙-전표 세 가지가 한 건으로 묶여야 합니다.

4. 전자세금계산서발행 — 매출 · 영세율 · 계산서 · 역발행

지도 연결 대금청구·세금계산서 · 송장 검증

하는 일

  • 매출이 확정되면 매출세금계산서를 발행합니다. 수출처럼 영세율이 적용되는 거래는 영세율세금계산서로 나갑니다.
  • 면세 거래에는 세금계산서가 아니라 계산서를 발행합니다.
  • 역발행세금계산서는 매입자 쪽에서 발행하는 형태로, 송장 검증 쪽에서 관리합니다.

FI 접점

대금청구 → 매출채권 / 매출 · 부가세 (매출세금계산서·영세율·계산서 발행)
역발행 수취 → AP / GR-IR (송장 검증)

주의점

  • 영세율과 면세(계산서)는 세법상 성격이 다릅니다. 세금계산서로 잘못 나가면 신고가 틀어집니다.
  • 발행분과 수취분은 각각 매출·매입 합계표로 모여 부가세 신고의 재료가 됩니다.

5. 부가세 및 원천세 신고

지도 연결 재무제표·세무신고

하는 일 — 월별 / 분기 주기로 합계표를 확인하고 전자 신고 파일을 만듭니다

  • 세금계산서 합계표: 세금계산서에 대한 부가세를 확인합니다.
  • 계산서 합계표: 계산서에 대한 부가세를 확인합니다.
  • 신용카드 수취명세서: 신용카드 사용분(매입·매출)의 부가세를 확인합니다.
  • 수출입 명세서: 영세율 내역을 확인합니다.
  • 부동산 임대공급 관련 신고: 간주임대료를 포함해 임대공급 내역을 정리합니다.
  • 공통매입세액 안분: 과세사업과 면세사업을 함께 영위하는 겸영사업자가, 공통으로 사용한 재화·용역의 매입세액을 과세 부분과 면세 부분으로 나눕니다. 근거는 부가가치세법 시행령 제61조 제1항이며, 예정신고 때 나눈 금액은 확정신고 때 정산합니다.
  • 원천세: 급여·사업소득 등에서 떼는 세금을 신고합니다. 급여 전표의 예수금-원천세와 연결됩니다.

FI 접점

합계표 확인 (월별/분기) → 전자 신고 파일 생성 → 홈텍스 신고
공통매입세액 안분 → 불공제 매입세액 확정 → 확정신고 시 정산

주의점

  • 합계표가 틀리면 신고가 틀립니다. 신고 전에 세금계산서·계산서·신용카드 세 가지 합계표를 각각 확인하는 것이 순서입니다.
  • 공통매입세액 안분은 사업장별로 계산한 뒤 합산해 신고하는 구조라, 사업장이 여럿이면 안분 기준을 먼저 통일해야 합니다.

6. 연결회계 솔루션

지도 연결 연결회계

하는 일

  • 각 자회사·사업장의 결산 데이터를 모아 연결 대상을 확정합니다.
  • 그룹 내부거래(내부 매출·매입, 내부 채권·채무)를 상계하고, 지분·투자 관련 연결 조정을 처리합니다.
  • 상계·조정 결과를 모아 연결재무제표를 작성합니다.

FI 접점

자회사 결산 데이터 수집 → 내부거래 상계 전표 (연결회계 노드) · 본지사 정리 → 연결재무제표 보고
상계가 안 맞으면 연결 단계에서 차이가 남으니, FI 내부거래 잔액이 먼저 맞아야 합니다.

주의점

  • 내부거래 상계는 양쪽 장부가 같은 금액·같은 기간이어야 성립합니다. 한쪽만 잡힌 내부거래가 연결에서 가장 많이 걸립니다.
  • 자회사마다 결산 일정·통화가 다르면 연결 일정이 늦어지니, 연결 일정과 환산 기준을 먼저 통일해야 합니다.
  • 연결 조정은 개별 회사 장부를 고치는 것이 아니라 연결 장부에서만 처리하는 것이 원칙입니다.

출처 · 범위

  • 부가세 관리: To-Be Process 정의서 FI-05-01(세금계산서·계산서·신용카드·수출입 합계표, 전자 신고 파일 → 홈텍스 신고, 월별/분기).
  • 인건비·퇴직급여: To-Be Process 정의서 FI-04-02-04(e-HR 월별 인건비 전표 전송, 급여/상여·예수금-원천세·복리후생비-4대보험 분개, 코스트센터 동일 정비, 퇴직급여 연초 계리액의 매월 1/12).
  • 경비·증빙·승인: Model Company 추적표 1.2.2 경비전표 및 증빙관리, To-Be FI 결산전표 항목.
  • 공통매입세액 안분: 참고자료(부가가치세법 시행령 제61조 제1항, 예정→확정신고 정산).
  • 연결회계: Model Company 추적표 1.7.4 연결회계, 이커머스·물류 리스트의 연결(그룹연결데이터관리·내부거래) 항목.
  • e-Accounting·전자결재 전용 정의서는 Drive에서 찾지 못했습니다. 그래서 이 두 영역은 기존 FI 정의서의 경비·증빙·승인 항목을 근거로 녹였고, 전용 자료가 나오면 그때 보강합니다.
  • 특정 업체·제품명, 고객사·프로젝트·금액·담당자 정보는 포함하지 않습니다.
